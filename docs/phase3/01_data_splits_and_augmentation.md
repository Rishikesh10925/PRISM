# Phase 3 / Tasks 2-3 — Data Splits & Augmentation Pipeline

## Splits (Task 2)

Generated by [src/detection/prepare_splits.py](../../src/detection/prepare_splits.py) into
`data/annotations/splits/{train,val,test}.txt` (one absolute image path per line) plus `split_summary.csv`.

The plan's target is a 70/15/15 split stratified by source, to avoid domain leakage between splits. That
rule is implemented for any source without its own predefined split. For **Pothole-600** specifically —
currently the only downloaded source, see
[docs/phase2/01_dataset_download_status.md](../phase2/01_dataset_download_status.md) — the dataset's own
train/validation/testing folders are honored instead of a fresh random split, because those folders were
deliberately built by the original authors to keep contiguous stereo-video frames on one side of the split
(reshuffling randomly would let near-identical adjacent frames leak between train and test). Sources without
a native split fall back to the 70/15/15 stratified random split automatically.

Current real split (582 images, after dedup):

| Split | Images | % |
|---|---|---|
| train | 239 | 41.1% |
| val | 172 | 29.6% |
| test | 171 | 29.4% |

This ratio (roughly 40/30/30) is Pothole-600's own split, not 70/15/15 — worth flagging explicitly since it
deviates from the plan's target. Once a second source with no native split is added, the stratified-random
path will start pulling the overall ratio back toward 70/15/15 for that source's share of the pool.

## Augmentation pipeline (Task 3)

[src/detection/augmentations.py](../../src/detection/augmentations.py) builds an Albumentations pipeline
(`RandomRain`, `RandomSunFlare` for glare, `MotionBlur`/`GaussianBlur`, `RandomBrightnessContrast`) —
Ultralytics' built-in augmentations cover geometric transforms and light HSV jitter but have no rain/glare/
motion-blur simulation, which road imagery specifically needs (blueprint Section 5.4).

Applied **offline** via [apply_offline_augmentation.py](../../src/detection/apply_offline_augmentation.py):
each training image gets one augmented copy written alongside the original in `data/merged/images/` (with
an identical label file, since these transforms are photometric-only — no crop/flip/warp — so polygon
coordinates don't change). This produces `train_augmented.txt` (478 images: 239 original + 239 augmented)
as a drop-in alternative to `train.txt`, which is exactly the toggle Phase 6 Task 5's augmentation ablation
needs: train once on each manifest, compare.

Chosen offline over an on-the-fly Ultralytics hook because it's simpler to unit-test (verified in
`src/detection/tests/test_augmentations.py` and `test_apply_offline_augmentation.py`) and trivial to
inspect by eye before spending GPU time on a training run.
